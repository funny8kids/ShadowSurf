## 1. 各成员核心结论

### 🛡️ 安全官（OWASP + STRIDE）

核心判断：**这一轮最严重的不是「没做」，是「做了但只做了一半，而做了一半比完全不做更容易被检出」。**

本轮最有价值的产出不是某一条漏洞，而是把「部分覆盖」归纳成一个可命名的模式：*同一事实存在多个 API 出口，只对齐了其中一部分，剩余出口报真实值，于是页面同时看到两套互相矛盾的读数*。不需要任何参照值就能判定被插桩。

这个模式在四个地方同时成立：`navigator`（掩码 14 / 赋值 11）、`Intl` 构造器（枚举 7 漏 2）、本地化方法（`Date` 接了 `Number`/`String` 没接）、闸门调用点（3 个里 1 个不传语义）。它比「某项能力没做完」有用，因为**能预测新洞**。

关键建议：`disabled` 模式改语义而不是注入 Worker。`session.ts` 在网络层已经关了非代理 UDP，JS 层删接口对 IP 泄漏的边际贡献是 0 —— 它只改外观，而外观恰好是矛盾的来源。

### ✅ 质量门神（QA + 发布）

核心判断：**这一轮我 6 次把正确行为当成 bug 要修，命中率约 1/3；实测命中率接近 1。**

站得住的结论全部来自先跑读数：Worker 露宿主真值（32 核 + 宿主时区）、`Intl` 清单漏项、`_IN`/`_RTC_KEYS` 字面量清单、23 个 RTC 接口。被推翻的全部来自「看代码觉得不对」。

关键建议：**断言要对着运行时行为写，不要对着源码形态写。** 源码级断言（`grep` 某个字符串存在）只能证明「有人写过」，证明不了「它生效」。本轮两次全红误报都出在这。

另附一条自曝：`AC-20` 第一版写成「两个符号必须存在」，写完全绿 —— 因为符号本来就在，等于测了空集。已改成断 stage-1 行为。

### 🔧 排障手（调试 + 根因）

核心判断：**`out/` 构建陈旧导致整轮结论漂移，这是流程缺陷不是代码缺陷。**

实测时间线：`out/main/index.js` 构建于 21:31，`fingerprint.ts` 改于 22:09，反检测门禁**不构建**直接读 `out/`。于是 AC-16 的「红」是修改前代码的读数，而报告上标的是当前 commit。

同一病根在一轮内出现三次：把工作区当 HEAD 测、把旧包当新包测、把规格里的名字（`stepHashes`）当已实现的东西。

关键建议：**能跑的就不要只读。** 任何「某处没做 X」的结论，先读该处完整控制流（含前后 10 行）+ 跑一条能证伪它的命令。

### 🔍 产品评审员（CEO / 工程 / DX 评审）

核心判断：**第三阶段 Chromium fork 的必要性，实测下来是零。**

用真实 Chrome 156 与仓库 Electron 45.2.1 逐项对比，「二进制不是 Chrome 的」这一整类差额只有两项：`window.chrome` 自有属性（3 vs 0）、EME stage-1 行为。其余 `Intl` 构造器数、`RTC*` 接口数、`navigator.plugins` 名字、`[object PluginArray]`、`typeof process` 全部逐字相同。

两项都能在 JS 层关掉，不需要内核工作。所以路线图应从「内核 fork」改成「内核适配器 + 指纹配置映射表」。

关键建议：优先级按「无需前提就会撞上」排，而不是按人日排。`_withTz` 覆盖显式时区只要 1 行，却同时修掉一个功能 bug 和一个 tell —— 全表投入产出比最高。

### 🎨 设计顾问（设计系统 + 视觉）

核心判断：**界面不得展示它无法验证的结论，也不得隐藏它无法保证的安全属性。**

本轮两个实例：`ApiPanel` 已经说了 80%（令牌位置、防截图、只监听 loopback），每句都在说「我们处理了」，而唯一该说的那句——令牌文件的读权限 = 任意环境的不可逆操作能力——恰好缺席。**部分披露比完全不提更误导**，因为用户以为问完了。

另一个：确认弹窗不能是渲染层画的。渲染层能自己调 `precheck` + `run`，弹窗可以不画。真正的落点是主进程独立窗口，而且它必须 import `tokens.css`，否则会成为第三份 CSS 漂移源。

关键建议：颜色不能是唯一的语义通道 —— 任何状态区分，去色后仍须成立。

## ⚠️ 已知局限（必须写进产品说明，不能只写进代码注释）

1. **词表法永远覆盖不了任意语言。** 本轮补了日韩俄德法西葡意，但第 15 种语言仍然会漏。终局是语言无关信号（`<form>` 内的 `type=submit` + 页面存在支付字段），需要 DOM 语义，属后续设计。
2. **本地 API 的信任边界 = 同用户身份的本地进程。** 任何能读 `local-api-token.json` 的进程，都可以在任意环境上执行 L2 动作。唯一门槛是 Bearer token，实现是对的（`randomBytes(32)` + `timingSafeEqual` + CORS 只放 loopback），但强度等于一个文件读权限。
3. **`has-own-frame` 是已接受的代价。** 全局 `Function.prototype.toString` patch 不能去掉 —— 迁移到 Proxy 也去不掉（名字正是被 patch 的 toString 给的）。触发需检测方主动踩异常路径，接受。
4. **`--lang` 不是解法。** 它是进程级开关，多环境共存时无法按 profile 切换，加了会让所有环境塌成同一语言。
5. **`navigator.gpu` 在 webgpu 开启时报宿主真实适配器。** CDP 无法覆盖 WebGPU，编一个假 `GPU` 对象成本远高于收益。
6. **`disabled` 模式不再让「WebRTC 不可用」，只是「不产生候选」。** 这是刻意的：接口层面的开关在 Worker 里关不掉，而「主世界没有、Worker 里有」是比不关更强的信号。副作用是页面仍能 `new RTCPeerConnection()` 并拿到 `signalingState` 等无地址信息 —— 这些本来也不泄漏 IP。
7. **`RTC_EXPECTED = 23` 是 Chromium 版本绑定值。** 升级内核后 AC-17 会红，这是设计意图（提醒有人核对接口清单），不是脆弱断言 —— 报错里带完整列表，照着改一行即可。之所以不写成「≥ 某数」，是因为「删了一半」正是要拦的东西。
