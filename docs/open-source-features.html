01为什么不做付费墙

不是道德姿态，是成本结构决定的。商业产品锁住的功能，绝大多数边际成本为零；它们被锁住，只因为锁住能卖钱。

1.1 两种成本，两种定价

成本类型典型项目边际成本合理商业模式
软件能力窗口同步、RPA、批量导入、API、团队权限、审计日志、指纹参数≈ 0（一次开发，无限复制）开源 / 一次性买断 / 赞助
运营服务内置代理流量、云同步存储、云手机、客服、代运营> 0（按量计费）按量付费，合理

商业产品的做法是把两类捆在一起卖：用零成本的软件能力做筹码，逼用户为有成本的服务付费。于是你为了「团队协作」这一个功能，不得不买一整套 100 环境的企业套餐。

本项目的取舍

软件能力全开：不设环境数上限、不设席位数、不锁 API、不锁同步器、不锁 RPA、不锁批量操作、不锁审计日志。
服务不自建：不做代理销售、不做云存储托管、不做云手机。需要这些的用户自行购买或自建——我们只提供接口，不赚差价。

1.2 不锁的四个工程理由

理由说明
分叉成本一旦有功能闸门，就必须维护两套代码路径（免费 / 付费）。开源项目没有足够人力维护分支逻辑，最终两边都会烂。
审计透明指纹浏览器的核心价值是「可验证」。带授权校验的闭源模块无法被社区审计，用户只能选择相信——这与开源的前提矛盾。
贡献动力贡献者不会为一个「自己用不到」的功能写代码。功能全开意味着每个用户都是潜在贡献者。
信任成本用户要在这类工具里登录几十上百个账号。任何「偷偷回传授权状态」的设计都会摧毁信任，而授权校验必然要联网。

1.3 我们明确不做的事

  • 不做代理/IP 销售：不内置任何代理套餐，不抽成。代理配置完全交给用户。
  • 不做云手机 / 真机农场：与浏览器隔离是两件事，硬凑在一起只会两边都不好用。
  • 不做破解与绕过：不提供「过验证码」「绕过风控」的成品能力。指纹一致性是技术问题，对抗平台规则是另一回事。
  • 不收集遥测：默认零上报。要统计就自己跑本地日志。

04指纹层

商业产品通常只给你「开关」——打开 Canvas 噪声、打开 WebGL 伪装。我们给的是种子、算法和参数表，因为只有这样才能验证一致性。

4.1 一条铁律：确定性，不是随机性

最常见的错误是「每次启动都随机化」。这在检测系统眼里等于自曝——同一个账号两次访问，Canvas 哈希变了、字体列表变了，风险分立刻飙升。

profile_seed = HKDF-SHA256(master_key, salt="ss-fp-v1", info=profile_id, 32 bytes)

canvas_noise(px)  = PRF(profile_seed, "canvas", px.x, px.y) % 3 - 1
webgl_vendor      = pick(profile_seed, "webgl", GPU_POOL)
font_list         = sample(profile_seed, "fonts", FONT_POOL, 42)
timezone          = pick(profile_seed, "tz", TZ_POOL_MATCHING_PROXY)

同一个 profile_id 永远得到同一套指纹；换 profile_id 得到完全不同的一套。种子存在加密库里，用户可导出、可迁移——这正是商业产品「环境迁移指纹不变」的实现原理。

4.3 一致性检测（这是「高级」的真正含义）

伪造单个参数不难，难的是让 50 个参数互相不矛盾。商业产品的「指纹评分」本质就是这张检查表：

4.4 反检测：别让 patch 被看出来

CreepJS 这类工具会检查「函数是不是原生的」：Function.prototype.toString.call(gl.getParameter) 必须返回 function getParameter() { [native code] }。包装函数如果直接赋值，一测就露。

const native = WebGLRenderingContext.prototype.getParameter;
WebGLRenderingContext.prototype.getParameter = new Proxy(native, {
  apply(target, thisArg, args) { /* 改写返回值 */ },
  // Proxy 天然保持 toString 外观
});

更稳的做法是不 patch JS，改内核返回值（Chromium fork 阶段）。扩展阶段用 Proxy + toString 伪装，能过大部分检测，但过不了深度检查——这一点要在文档里说清楚，不能让用户误以为扩展版等于内核版。

5.2 迁移包格式

「指纹不变地搬家」是商业产品的核心卖点之一，实现上并不复杂，难的是密钥管理：

profile-8848.ssp  (zip)
├── manifest.json      { version, profile_id, exported_at, algo: "aes-256-gcm" }
├── seed.enc           种子密文（用导出密码派生密钥，scrypt）
├── cookies.enc        加密的 Cookie 存储
├── config.json        代理、启动参数、标签（不含密钥）
└── checksum.txt       SHA-256，导入前校验完整性

导入时的三种情况：

情况处理
本机无同 ID 环境直接导入，沿用原 profile_id，指纹与原来完全一致
本机已有同 ID提示二选一：覆盖（保留原 ID）或另存为新环境（分配新 ID，指纹随之改变，需明确告知）
密码错误 / 校验失败拒绝导入，不做任何部分写入（先解压到临时目录校验，通过后再入库）

5.3 为什么「不存明文指纹」

环境表里只存 seed 与少量可读元数据（平台族、GPU 名），完整指纹在启动时由种子现算。三个好处：

  • 防泄漏：数据库被拖走，攻击者拿到的是密文种子，没有 master key 算不出指纹。
  • 防漂移：算法升级（比如新增一个参数）后，所有环境自动获得新参数，不需要迁移数据。
  • 体积小：一万个环境的元数据不到 10MB，启动时算一次指纹只要几毫秒。

06代理与网络

指纹和 IP 是两条腿。腿不齐，指纹做得再好也没用。商业产品把代理流量打包进套餐卖，我们只做代理管理，不卖代理。

6.1 六项能力

能力行为实现要点优先级

批量检测并发测试 N 条代理：连通性、延迟、出口 IP、地理位置、是否透明代理请求 ipinfo 类接口比对 IP 与 ASN；并发上限 20，避免把自己打限流P0

6.2 带认证的代理怎么接

这是新手最常卡住的地方：Chromium 的 --proxy-server 不支持 user:pass@host，而绝大多数付费代理都要认证。两种解法：

方案 A（推荐）：本地转发器
  浏览器 --proxy-server=127.0.0.1:PORT
  本地进程 → 连上游代理 → 注入 Proxy-Authorization → 转发
  优点：支持链式、支持流量统计、支持失败切换

方案 B：扩展拦截 onAuthRequired
  chrome.webRequest.onAuthRequired 提供凭据
  优点：零额外进程；缺点：仅扩展阶段可用，无法统计流量

6.3 一致性自动修正

绑定代理的那一刻，是最容易产生矛盾的时刻。默认策略是自动跟随，而不是让用户手动对表：

代理出口自动设置理由
美国 · 洛杉矶时区 America/Los_Angeles，语言 en-US，Accept-Language 同步三处必须一致，否则一次 JS 探测就露
日本 · 东京时区 Asia/Tokyo，语言 ja-JP + en-US 备选日本用户常见双语列表
住宅代理（不透明）不改时区，仅记录住宅 IP 的地理位置本身模糊，强行改反而奇怪
检测到透明代理拒绝绑定并提示透明代理会把真实 IP 写进 X-Forwarded-For，等于没代理
不做的事

不内置代理销售、不做「IP 质量评分」的付费墙、不代理任何机房 IP 转售。代理池是用户自己的资源清单，我们只负责分配与检测。

不做的事

不内置代理销售、不做「IP 质量评分」的付费墙、不代理任何机房 IP 转售。代理池是用户自己的资源清单，我们只负责分配与检测。

7.3 RPA 与 AI 共用一套动作协议

这是本项目相对商业产品的一个结构性优势。商业产品里，RPA 是 RPA，AI 助手是 AI 助手，两套东西互不相通。我们把它们统一到同一个动作模型上：

来源产出执行
人工录制[{type:'click',id:'e3'},{type:'type',id:'e5',text:'…'}]同一个执行器
AI 决策{type:'click',id:'e3'}（每步一个）同一个执行器
手写脚本同上，JSON 或 YAML同一个执行器

好处是三重的：

  • AI 能修 RPA：脚本跑失败时，让 AI 看当前页面重新定位元素，改完继续——不需要人工重录。
  • RPA 能降 AI 成本：稳定流程录成脚本后不再调用模型，成本从每步一次请求降到零。
  • 一套测试：执行器的边界情况（元素消失、页面跳转、iframe）只需测一遍。

7.4 窗口同步器怎么做

同步器看着简单，实际有两个坑：坐标和时序。

主窗口 CDP Input.dispatchMouseEvent 事件
  ↓
归一化：nx = x / viewport.width, ny = y / viewport.height
  ↓
从窗口还原：x' = nx * w', y' = ny * h'
  ↓
逐个派发（错开 20–40ms，避免同时请求打满 CPU）
坑处理
分辨率不同归一化坐标；若从窗口视口比例与主窗口差异 > 15%，标记该窗口为「不同步」并提示
页面布局不同同步的是坐标不是元素，布局差异会导致点错。所以同步器只适用于「同一套页面模板」的场景（如同一后台的多个账号）
输入法 / 组合键输入事件按字符广播而非按键广播，避免中文输入法在从窗口丢字
滚动按滚动比例同步，不按像素
为什么同步器要放在 P1

它依赖 CDP 事件捕获与多窗口协调，工程量大但适用面窄（只对同模板页面有效）。首版先把 REST + CDP + RPA 做扎实，同步器排第二期。这也是「不因为商业产品收费就盲目跟」的判断——功能全开不等于功能堆砌。

8.3 审计日志的哈希链

普通日志可以删、可以改，出事时不能当证据。做法是让每条记录都包含上一条的哈希：

entry_n.hash = SHA256( entry_{n-1}.hash || timestamp || actor || action || target || detail )

想偷偷删掉中间一条，后面所有 hash 全部对不上。校验接口 GET /audit/verify 会从第一条重算，返回第一个断裂点。这是商业产品也很少做的细节，但它是「审计」这个词的底线。

09安全与数据

指纹浏览器的数据库里躺着几十上百个账号的登录态。它本质上是一个高价值凭据仓库，安全等级应该按这个标准来要求。

9.2 密钥层级

用户主密码
   │  argon2id (m=64MB, t=3, p=4)
   ▼
master_key ──┬──► 解密 SQLCipher 数据库
             ├──► HKDF("ss-fp-v1", profile_id) ──► 每个环境的指纹种子
             └──► HKDF("ss-exp-v1", profile_id) ──► 导出包密码校验

一条重要规则：master_key 永不落盘、永不上网。导出包用独立的导出密码重新加密，这样「把环境发给同事」不需要交出主密码。

9.3 数据存什么、不存什么

数据存储说明
环境配置、指纹种子加密核心资产，必须加密
Cookie / LocalStorage加密等于账号本身
代理凭据加密泄漏即被白嫖流量
操作审计日志明文 + 哈希链需要可查询，靠哈希链保证完整性
页面快照 / 浏览历史不存浏览内容不留痕，与 AI 模块的设计一致
模型 API Key本地配置与 AI 面板共用，明文存储但仅本机
一个必须说清楚的取舍

主密码丢了，数据就真的打不开了——我们不设后门，也没有「找回」通道。这是加密的必然代价。UI 上必须在设置主密码时强制确认一次，并提供「导出恢复密钥」的选项。

13边界与合规

13.1 功能不设限，行为有边界

事项立场
开源协议代码采用 MIT（与仓库 LICENSE 一致），允许商用、修改、闭源二次开发。不采用 AGPL——避免把用户的自建服务也拖进传染范围。
不做破解不提供「绕过平台风控」「破解验证码」「伪造实名」的成品能力。指纹一致性是技术问题，规避平台规则是另一回事。
不卖资源不销售代理 IP、不销售账号、不提供代运营。所有外部资源由用户自行采购，我们不抽成、不背书。
零遥测默认不上报任何数据。崩溃日志、使用统计一律本地保存，用户主动导出才会离开机器。
责任边界工具中立，用途由使用者负责。文档里明确写：多账号运营需遵守目标平台的服务条款与当地法律。

13.2 贡献者需要知道的

  • 不合并：任何形式的授权校验、功能闸门、按次计费的补丁。
  • 不合并：绕过第三方服务技术保护措施的代码。
  • 需附测试：指纹相关改动必须附带一致性测试（同一 seed 两次启动结果一致）。
  • 需核 License：引入新依赖时在 PR 里注明协议，AGPL 依赖一律拒绝。

14验收标准

功能「做完」和「能用」是两件事。每条能力都要有一个可执行的验收动作。

#验收项通过标准
1指纹确定性同一环境连续启动 10 次，Canvas / WebGL / Audio 哈希完全一致
2指纹差异性两个不同环境启动，上述三项哈希均不同
3一致性无矛盾一致性校验器对默认模板返回 0 个矛盾项
4WebRTC 不泄漏绑定代理后，检测页面读不到真实内网 IP
5时区跟随代理绑定美国代理后，Intl 时区为 America/*，且与 Date 偏移一致
6迁移保真导出再导入到另一台机器，指纹哈希不变、登录态保留
7批量创建一次创建 100 个环境 < 10 秒，且种子无碰撞
8列表性能10000 个环境时，列表首屏 < 300ms，筛选 < 100ms
9代理认证带用户名密码的 SOCKS5 代理可正常联网，且页面读不到认证信息
10API 无限流连续 1000 次 REST 调用无 429
11CDP 接入Playwright connectOverCDP 后，指纹与代理仍然生效
12权限隔离只读账号调用删除接口返回 403，且日志有记录
13审计防篡改手工修改数据库一条日志后，/audit/verify 能定位到断裂点
14环境锁两个客户端同时启动同一环境，第二个被拒绝并提示持有者
15加密强度直接打开数据库文件，看不到任何明文 Cookie 或种子
16无付费闸门全代码库搜索不到 license / plan / tier / 授权校验相关逻辑
一句话总结

商业产品锁住的 47 项能力，41 项在阶段二就能全开，因为它们本来就是零边际成本的软件能力。真正需要成本的只有代理流量和云存储，那两样我们不自建、不赚差价。功能全开的代价不是收入，而是维护责任——这才是开源项目真正要扛的东西。
