ShadowSurf 界面与交互对标评审

本文把 ShadowSurf 的渲染层与 Linear、Raycast、Arc、Chrome 146+、Firefox 157 逐维对齐，并与 AdsPower、GoLogin、Multilogin、BitBrowser 的操作面交叉核对。所有结论只写能在源码里指出 file:line 的事实，或能在远程实拍里复现的现象；不写「业界惯例」这类无法复核的句子。改法一律具体到 CSS 属性与取值。

01结论先行

五条结论。每一条后面都跟着可复核的 file:line 或可复现的操作，不写「设计上应该」这种没有落点的句子。

01

问题不在审美，而在栅格不统一

工具页的缩进是 26px，环境页是 24px：app.css:578 写的是 24px，而 proxy.css:12 等把它覆盖成 26px。切页时内容左边界横移 2px，标题、表头、卡片第一列全部跟着跳。Chrome 与 Linear 的做法是单一 --page-pad 贯穿所有页面；这里有两套值，而且没有一处是 token。证据：app.css:578、proxy.css:12。

02

交互语义错位：看不见的东西仍然可点

.env-actions 用 opacity:0 隐藏（app.css:1286-1299），但没有 pointer-events:none——右下角空白处会点到看不见的「配置 / 打开」。标签关闭 X 同理（app.css:2225），而且 BrowserShell.tsx:306 写死 tabIndex={-1}，键盘完全不可达。Raycast / Arc 的等价控件是「hover 才出现，但出现时始终可聚焦」；这里连「出现时」都没做到。

03

动效只进场不退场

Modal（ui.tsx:487）、CommandPalette（CommandPalette.tsx:86）、Toast（ui.tsx:558）、批量条（ProfileGrid.tsx:459）全部是 unmount 瞬切，没有退场帧。.cp-closing 的退场动画已经在 command-palette.css:61-67 写好，但全仓库 0 处引用。Arc / Raycast 的浮层退出是 120–180ms 加速曲线，不是「消失」。

04

三套刻度没落地

字号硬编码 286 处（var(--fs-*) 仅 46 次）、动效时长硬编码 56 行（0.14s 出现 34 次）、圆角 110 / 232 绕过 token、间距约 175 处不在 4px 网格、--sp-* 在 app.css 里 0 次引用。密度开关因此名不副实：切到紧凑，主界面几乎不动——它只改了部分 chrome 尺寸，没有改内容间距。

05

三态与对比度意识属上乘

9 个面板中 8 个已经三态化；只有 ApiPanel 仍把「读不到」渲染成「已停止」（ApiPanel.tsx:172-177）。--ink-4 的对比度只有 3.08:1（tokens.css:66-71），却用在 86 处说明文字上，未达 WCAG AA 的 4.5:1。所以问题不是「不懂可访问性」，而是令牌值本身没达标——这是改一个值的事，不是重做体系的事。

读法

这些数字的共同点是「值对、来源不对」——每个字号、圆角、时长都能在界面上找到对应，但没有一条来自令牌。所以改法不是重画，而是把它们替换回 var(--fs-*) / var(--r-*) / var(--dur-*)。这也是本文把「格式问题」与「审美问题」分开的原因：格式问题可以逐条替换，审美问题才需要重新设计。

03交互丝滑度问题

这一节只写会改变操作结果的缺陷，以及会让界面「看起来卡」的缺口。编号与 §05 的差距清单一一对应。

3.1 隐身可点：两个 P0

P0-5 · 环境操作区

  • 现象：环境卡片右下角有一片空白，点下去会触发看不见的「配置 / 打开」。
  • 证据：app.css:1286-1299 用 opacity:0 隐藏 .env-actions，没有 pointer-events。CSS 里 opacity:0 只影响绘制，不影响命中测试。
  • 对标：Raycast 的隐藏操作在出现时仍可聚焦，未出现时完全不接收指针。
  • 改法：.env-actions{opacity:0;pointer-events:none}；.env-card:hover .env-actions,.env-actions:focus-within{opacity:1;pointer-events:auto}。focus-within 必须保留，否则键盘用户永远进不去。

P0-6 · 标签关闭键

  • 现象：标签未 hover 时关闭 X 不可见，但鼠标经过那片区域会点到它；键盘 Tab 永远到不了。
  • 证据：app.css:2225 关闭键用 opacity:0 隐藏；BrowserShell.tsx:306 写死 tabIndex={-1}。
  • 对标：Chrome 的标签关闭键始终在 tab order 里，视觉可以淡，焦点不能断。
  • 改法：移除 tabIndex={-1}，补 aria-label="关闭标签"；opacity 只控制视觉，命中区保持 24×24。

3.2 溢出与键盘

P0-7 · 标签溢出硬裁

  • 现象：标签多了以后，文字被直接裁掉，没有最小宽度，也没有溢出入口。
  • 证据：app.css:2136 容器 overflow:hidden；.btab 没有 min-width。
  • 对标：Chrome 标签先缩到下限，再出 chevron；Firefox 157 的紧凑模式也是缩到下限而不是裁字。
  • 改法：.btab{min-width:120px}；容器改 overflow-x:auto，或加一个「更多标签」溢出菜单。

P0-8 · 命令面板方向键不滚动

  • 现象：结果超过一屏后，方向键能改选中项，但选中行滚出可视区，用户看不到自己在哪。
  • 证据：CommandPalette.tsx:97-105 只更新 activeIndex，没有调用 scrollIntoView。
  • 对标：Raycast / Linear 的选中项始终保持在视口内，方向键与滚动同步。
  • 改法：active 变化时 ref.current?.scrollIntoView({block:'nearest'})，包在 useEffect 里。

3.3 焦点与草稿

P0-9 · 抽屉无焦点管理且静默丢草稿

  • 现象：打开指纹抽屉后焦点留在原来的按钮上；按 Esc 或点遮罩关闭，填了一半的草稿直接消失，没有确认。
  • 证据：FingerprintDrawer.tsx:240-243 关闭路径只 setState，没有焦点还原，也没有草稿持久化。
  • 对标：Linear 的抽屉打开即聚焦首个字段、Tab 锁在抽屉内、关闭后焦点回到触发按钮。
  • 改法：打开时 firstField.focus()；keydown 里 trap Tab；草稿写 localStorage 或关闭前 confirm；关闭后 trigger.focus()。

P0-10 · 焦点环被抹掉

  • 现象：键盘焦点几乎看不见；少数替代光环的对比度只有约 1.1:1。
  • 证据：全渲染层 outline:none 12 处；替代光环与背景对比度约 1.1:1。
  • 对标：WCAG 2.2 SC 2.4.13 要求焦点指示器与未聚焦态同像素对比度 ≥ 3:1。
  • 改法：删掉 outline:none，统一 :focus-visible{outline:2px solid var(--focus-ring);outline-offset:2px}；把 --focus-ring 提到 ≥3:1。

3.4 任务页三态

P0-12 · 330px 装不下三态

任务页左栏宽度是 330px（app.css:3574），empty / loading / error 三种状态共用这一栏。错误文案一换行就挤压操作按钮，空态插图也被压成一条。Linear 的做法是空态与错误态占满右侧内容区，左栏只保留列表与筛选。

改法：左栏改 grid-template-columns:minmax(360px,420px) 1fr；把 empty / error 移到右侧主区；loading 用骨架屏占位，不要用一行「加载中…」。

这一节的判断

P0 的六条都会改变操作结果：点到看不见的按钮、标签关不掉、抽屉丢草稿、焦点看不见。P1 的八条不改变结果，但会让界面「看起来卡」或「看起来不跟手」。先修 P0，再修 P1；P1 里最先做的是退场动画与视图过渡，因为它们同时影响「高级感」和「操作确定性」。

05差距清单（按优先级）

P0 必修 15 条、P1 应修 18 条、P2 打磨 12 条。每条写「问题 + 证据 + 对标 + 改法」，改法具体到 CSS 属性或组件调用。

P0
必修 · 15 条
会改变操作结果

先把「格式不对」与「点错东西」修掉

06三条不可动摇的结论

这三条不是建议，是本轮评审的边界。越界就会把已经做对的东西一起推翻。

结论一 · 不要为了「现代感」重做整个设计系统

事实：令牌注释、三态规范、对比度意识这三件事，本项目已经做到了多数商业产品没有的程度。tokens.css 的每一组令牌都有注释；docs/DESIGN.md 写死了「不可判读状态」的判定标准与修法形式；9 个面板里 8 个已经三态化。重做会丢掉这些正确性——新系统看起来更「现代」，但会重新引入布尔量判断、会把 error 又压成 toast、会让对比度重新变成 3:1。

正确做法：在现有令牌上做替换与补档，不重画。先改 --ink-4 与 --page-pad 两个值，再逐条替换字号、圆角、时长字面值。设计系统的问题从来不是「不够新」，是「令牌没有被使用」。

结论二 · 优先修栅格与交互语义

事实：P0-1 / 2 / 3 / 5 / 6 / 7 / 8 全部是「格式不对」或「点错东西」：栅格 26px 与 24px、切页横跳、隐身可点、标签关闭不可达、标签溢出硬裁、命令面板方向键不滚动。这七条不需要新设计，只需要改属性与事件绑定。它们是根因，不是表象。

顺序：先 --page-pad 与 pointer-events，再 min-width 与 scrollIntoView，最后 tabIndex 与 outline。这七条修完，界面的「格式感」会立刻对齐 Chrome / Linear；之后再谈动效与密度，才不会像在给歪的地基刷漆。

结论三 · 密度 / 圆角 / 字号三套刻度必须真正落地

事实：--sp-* 在 app.css 里 0 次引用；圆角 110 / 232 绕过 token；字号 286 处硬编码，--fs-* 仅 46 次。密度开关切到紧凑时，主界面几乎不动——开关名不副实，比没有开关更伤信任。

验收线：密度切换后，页面间距按 0.75 变化且字号不变；app.css 内 margin / padding 全部走 --sp-*；圆角全部走 --r-*；字号全部走 --fs-*。三条都达标，才算「刻度落地」；否则密度只是一个改了 chrome 高度的装饰开关。

一句话总结

ShadowSurf 的界面不是「不好看」，是「格式没有统一来源」。把栅格收成一个 token、把交互语义补正、把三套刻度真正用起来，界面的完成度会比现在高一个档——这比换一套配色或重画组件库便宜得多，也安全得多。
