01设计原则

原则具体做法反面案例
状态先于操作每个环境卡在左上角先给状态点与编号，再给操作按钮。用户扫一眼就知道哪些在跑、哪些挂了把"启动"做成大按钮，用户点下去才发现代理不通

2.1.1 深色主题

深色不是简单反色：画布压到近黑（#0A0C0F）降低眩光，强调色换成高亮度 teal（#2DD4BF）——原来的深青在深底上对比度不足。语义色统一改为「9% 透明度做底、纯亮色做字」，保证在暗背景上仍能分辨四种状态。

为什么强调色要拆成两个令牌

同一个 --accent 既要当按钮填充底、又要当链接文字色。亮色主题下 #0F766E 两件事都成立；暗色主题下数学上不可能：当文字要在近黑底上够亮（需要高明度），当填充底又要让上面的字够亮（需要低明度）。所以拆成 --accent（填充/边框/图标）与 --on-accent（压在上面的文字）。暗色下强调色取亮青 #2DD4BF，配深墨 #04211E 约 9:1；若沿用白字只有 2.1:1。

主题怎么切

亮色是 :root 默认值，暗色是 [data-theme='dark'] 的整套覆盖，属性挂在 <html> 上。组件里不写 @media (prefers-color-scheme)：两套机制并存时，「用户手动选亮色 + 系统是深色」会同时命中两个分支，谁赢取决于样式表顺序，这种 bug 读代码看不出来。系统偏好只在 src/renderer/lib/theme.ts 里读一次。

模式的解析（含「跟随系统」）在主进程 src/main/core/theme.ts 做，窗口底色与令牌由同一处铺开；渲染层只消费 'light' | 'dark'。用户的 ThemeMode 三档（system / light / dark）原样落盘，不折成具体亮暗——折了之后用户就再也回不到「跟随系统」。

对比度由 npm run verify:theme 在真实应用里量：遍历所有可见叶子文本节点、合成实际背景色、算 WCAG 比值，非装饰文本低于 3.0 判失败。渐变背景无法解析，记为「未测量」而不是「通过」。

场景呈现可执行动作
加载中6 张骨架卡（灰块，带 1.2s 微光扫过）无

5.2 边界处理

  • 环境超过 60 个：虚拟滚动，卡片保持固定高度 148px。
  • 名称过长：单行省略，hover 显示 tooltip 全名。
  • 代理 IP 过长：等宽字体，超出时省略中段（45.132…8.21:8000）。
  • 批量操作部分失败：不整体回滚，用 Toast 汇总"成功 3 个，失败 1 个"，点击展开失败明细。

分组字段控件

交互细节

点"骰子"只改这一个字段，但会立刻触发一致性重算——如果新值与其它字段冲突，分数实时下降并高亮冲突项。这样用户能建立"字段之间有关联"的直觉，而不是攒一堆随机值到启动时才发现不匹配。

07双轨窗口（P0）

项规格
页面目标让用户直观看到"影子在另一个空间里干活，我在自己的空间里不受影响"
数据源POST /v1/spaces · POST /v1/tasks · 事件 task.step · GET /tasks/{id}
结构窗口标题栏 → 双组标签栏 → 地址栏 → 左右分屏（57 / 43）→ 底部 Agent 控制条
分组左侧「人」标签组，右侧「影子」标签组，中间 1px 分隔线；影子标签带深青图标与旋转加载环

7.1 影子区的三重标识

标识实现作用
斜纹底纹45° 斜纹，线宽 7px、间隔 15px、深青透明度 4.2%余光可辨"这不是我的窗口"，但对比度低不干扰阅读
虚线边框左侧 1px dashed #bcd3ce明确边界，暗示"临时 / 隔离"
空间徽章左上角「影子 Space · 独立会话」，白底 90% 不透明 + 6px 模糊新用户第一次看就理解发生了什么

7.2 Agent 控制条

高度 66px，三段式：

  • 左：30×30 图标块（品牌渐变），建立"这是 AI 在说话"的视觉锚点。
  • 中：当前动作（12.5px 加粗）+ 步骤徽章 12 / 20 + 说明文字（10.5px）+ 20 格进度条（每格代表一个条目，已完成实心、当前半透明）。
  • 右：暂停（ghost）与 接管（描边强调）。接管按钮必须常驻，不能收进菜单。
禁止事项

影子空间不得触发以下行为：抢占窗口焦点、弹出系统通知、在用户标签页上覆盖遮罩、自动切换用户当前标签。所有状态变化只通过控制条与侧边栏徽章表达。

09新建环境向导（P1 · 规划）

三步向导，把"建一个能用的环境"从 8 个字段压缩到 3 个决策。目标：从点击到可用 ≤ 30 秒。

步骤内容默认值校验
1 系统选操作系统（4 个卡片：Win10 / Win11 / macOS 14 / 15），自动推导 UA、分辨率、WebGLWin11—
2 网络选代理（从池中挑 / 粘贴新代理），显示出口地区与延迟最近使用的代理连通性检测，失败可跳过
3 校验实时一致性评分 + 冲突列表 + "一键修复"，命名与分组自动命名 Win11-US-01分数 < 90 时"创建"按钮降级为次要
设计取舍

不把指纹字段全暴露在向导里。90% 的用户只需要"一个看起来正常的美国 Windows 环境"，而不是 20 个可调参数。高级用户走"创建后进抽屉细调"的路径。

10窗口同步器（P2 · 规划）

指纹浏览器的招牌功能，也是影子批量执行的天然入口：一个操作，同步到 N 个环境。

能力交互技术约束
窗口平铺2×2 / 3×2 / 4×3 三种布局，按环境数自动选择每个窗口独立 Space，独立 BrowserContext
主控窗口点击任一窗口右上角"设为主控"，边框变深青主控的输入事件广播到其余窗口
同步范围滚动 / 点击 / 输入 / 导航，可勾选坐标按各窗口视口比例映射，不按绝对像素
影子接管勾选"由影子执行"，主控操作变成任务模板需先跑通单环境，再复制到 N 个
风险提示

同步操作在风控严格的站点上极易触发关联判定。UI 必须在开启同步时显示一次性警告，并在检测到验证码时自动暂停全部窗口、逐个转人工。

11.2 焦点管理

  • 抽屉打开时焦点移入第一个可交互元素，并在抽屉内循环（焦点陷阱）；关闭后返回触发按钮。
  • 双轨窗口打开时焦点留在 UI，不自动聚焦到页面内容——避免用户误输入。
  • Toast 不抢焦点，用 aria-live="polite" 播报。

11.3 加载策略

场景策略理由
首屏列表骨架屏（6 张卡）保持布局稳定，避免跳动
抽屉打开立即显示框架，字段区骨架感知延迟最低
Toggle 切换乐观更新 + 失败回滚开关是高频操作，等 300ms 会烦
任务启动按钮转 loading，不阻塞列表用户可能连续启动多个
步骤推送增量插入，不做整列表重渲染每步都有新数据，重渲染会闪

字段级输入框下方 11px 红字环境名称超过 64 字符
操作级Toast（error 常驻，手动关）批量启动中 1 个代理超时
页面级整块错误状态 + trace_id + 重试列表加载失败
阻断级Modal，必须处理L2 动作待确认、指纹不一致阻止启动

12可访问性

  • 对比度：正文 ≥ 4.5:1，大字号 ≥ 3:1，禁用态也需 ≥ 3:1（不用 opacity 降到看不见）。
  • 焦点环：2px solid var(--accent) + offset 2px，禁止 outline: none。
  • 语义：卡片用 article，列表用 ul/li，抽屉用 role="dialog" aria-modal="true"。
  • 状态播报：任务状态变化用 aria-live="polite"，错误用 assertive。
  • 不依赖颜色：状态点必须配文字（"影子执行中 3/5"），不能只用绿点。
  • 动效：响应 prefers-reduced-motion，关闭脉冲与滑入。
  • 触控目标：最小 24×24，卡片上的复选框视觉 14px 但点击区扩到 24px。

14.1 本地化

  • 默认简体中文，预留英文。所有文案走 i18n key，不硬编码。
  • 中文文案长度按英文的 0.7 倍估算，布局按英文（更长）预留空间，避免切换语言后溢出。
  • 数字与日期用 Intl.NumberFormat / Intl.DateTimeFormat，不手工拼接。
  • 环境名称、分组名允许任意 Unicode，但做长度校验（64 字符）。
